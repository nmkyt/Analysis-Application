## Данные

Модель учётной системы сети из шести металлобаз в PostgreSQL: каталог, клиенты, поставщики,
цены, заказы, поставки, перемещения между базами и движение товаров по складам.
Все таблицы выгружены в CSV в [`data/`](data), с ними проект работает без PostgreSQL.

> **Данные синтетические.** Структура сети, ассортимент и услуги смоделированы по публичной
> информации о компании из дипломной работы. Объёмы продаж, клиенты, цены, поставщики и остатки
> вымышлены и не являются данными ООО «Металл-Маркет».

| Период | октябрь 2021 — сентябрь 2026 |
|---|---|
| Ассортимент | 927 позиций в 62 категориях: черный и оцинкованный прокат, трубы, сетки, метизы, фитинги, нержавейка, цветной металл, готовые изделия |
| Клиенты | около 29 тыс.: частные лица, мелкие строители, строительные компании, производства, перепродавцы |
| Заказы | около 250 тыс. заказов и 940 тыс. строк, около 156 тыс. т металлопроката |

## Прогноз спроса

Прогноз продаж каждой позиции на каждой базе — 3 347 рядов — на 1–4 недели вперёд.
Одна модель градиентного бустинга на все ряды, отдельная на каждый горизонт; продажи
нормируются на масштаб ряда. Качество проверяется на последних 26 неделях данных
и сравнивается с простыми прогнозами-ориентирами.

Тест 30.03 — 27.09.2026, прогноз на неделю вперёд, ошибка в килограммах:

| | WAPE | Bias | R² |
|---|---:|---:|---:|
| **модель** | **84,7 %** | +8,3 % | **0,54** |
| как неделю назад | 102,4 % | +0,7 % | 0,20 |
| как год назад | 101,2 % | −3,8 % | 0,19 |
| среднее за 4 недели | 87,2 % | −0,1 % | 0,49 |

Модель лучше ориентиров на всех горизонтах. Ошибка 85 % — по отдельной позиции на отдельной
базе за неделю, где спрос прерывистый; по всей сети недельная ошибка — 12,5 %. Главное
ограничение — прогноз завышен на 8 %, отчасти из-за дефицита в конце теста.
Подробнее — в [docs/metrics.md](docs/metrics.md).

## Структура репозитория

```
src/sales_analytics/    устанавливаемый пакет
├── storage/            учётная система в PostgreSQL, чтение базы и датасета
├── forecasting/        предобработка, модель, прогноз, графики
└── api/                REST API на FastAPI
data/                   датасет: таблицы учётной системы в CSV
docs/                   документация и графики
tests/                  юнит-тесты (pytest)
infra/                  PostgreSQL в Docker
output/                 модели, прогнозы и выборки (создаётся при запуске, не хранится в git)
```

## Запуск

Нужен Python 3.13:

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -e .        # в Linux/macOS: .venv/bin/python
cp .env.example .env
```

### REST API

Основная точка входа:

```bash
python -m sales_analytics.api        # http://127.0.0.1:8000, адрес и порт - API_HOST и API_PORT в .env
```

На http://127.0.0.1:8000/docs — документация, где любой запрос можно выполнить из браузера.
Обычный порядок: `POST /models/train` → `GET /jobs/{id}` → `POST /forecasts` → `GET /forecasts/latest`.
Все эндпоинты и пример с `curl` — в [docs/application.md](docs/application.md#эндпоинты).

### Командная строка

PostgreSQL не нужен: с `--data data` данные читаются из датасета.

```bash
python -m sales_analytics.forecasting train --data data                # обучение на 1–4 недели
python -m sales_analytics.forecasting train --data data --horizon 1    # только на неделю вперёд
python -m sales_analytics.forecasting predict --data data              # прогноз после конца данных
python -m sales_analytics.forecasting report                           # графики в docs/images
```

Результаты сохраняются в `output/` — см. [docs/application.md](docs/application.md#результаты).

### База данных

Нужен PostgreSQL 15+ — установленный или в Docker, пароль указывается в `.env` (`DB_PASSWORD`).

```bash
docker compose --env-file .env -f infra/docker-compose.yml up -d   # PostgreSQL в контейнере
python -m sales_analytics.storage init                             # или роль и база на установленном PostgreSQL
python -m sales_analytics.storage create --yes                     # таблицы
python -m sales_analytics.storage export                           # выгрузка таблиц в data/
```

Без `--data` команды `train` и `predict` читают данные из базы.

### Тесты

Работают на маленьких искусственных данных, PostgreSQL и датасет не нужны:

```bash
.venv/Scripts/python -m pip install -e ".[dev]"
python -m pytest
```
