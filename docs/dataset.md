# Датасет

Выгрузка всех таблиц учётной системы сети металлобаз из PostgreSQL — справочники, цены, продажи,
закупки, перемещения и движение товаров по складам — лежит в [`data/`](../data). Здесь — откуда
данные, что в них заложено, как устроены файлы и почему. Модель данных — в [database.md](database.md).

## Почему данные синтетические

> **Данные синтетические.** Структура сети, ассортимент и услуги смоделированы по публичной
> информации о компании из дипломной работы. Объёмы продаж, клиенты, цены, поставщики и остатки
> вымышлены и не являются данными ООО «Металл-Маркет».

Выбор синтетических данных — вынужденный, но у него есть и методические плюсы.

1. **Настоящие данные недоступны и не могут быть опубликованы.** Продажи по позициям, клиенты
   и закупочные цены — коммерческая тайна. Проект открытый, и любой результат в нём должен
   воспроизводиться без доступа к учётной системе компании.
2. **Данных дипломной работы недостаточно.** В 2024 году модель обучалась на таблице
   из 168 месячных строк с выручкой и продажами по пяти категориям. На таких данных нельзя
   поставить задачу прогноза по позициям и складам, а случайный лес на 168 строках почти
   не отличается от усреднения.
3. **Известно, что заложено в данные.** На реальных данных нельзя проверить, видит ли модель
   сезонность или реакцию на дефицит, — неизвестно, есть ли они там. В синтетических данных эффекты
   заданы явно, и можно проверить, какие из них модель улавливает, а какие нет.

Главный риск синтетики — модель научится восстанавливать правила генератора, а не реальный
спрос. Поэтому данные строятся как **учётная система**, а не как готовый ряд для обучения:
продажи возникают из отдельных заказов отдельных клиентов, остатки — из движения товаров
по складу, и модель видит только то, что видела бы на настоящих данных, — агрегаты продаж
из документов.

### Свойства, важные для прогноза

Данные специально сделаны трудными в тех местах, где трудна настоящая металлоторговля.

| Свойство | Как проявляется | Что это значит для модели |
|---|---|---|
| **Прерывистый спрос** | в 58,7 % недель ряда продаж нет | нужна функция потерь, работающая с нулями; MAPE неприменим |
| **Разный масштаб рядов** | средние продажи ряда в неделю — от 0,14 до 1 095 единиц (1-й и 99-й процентили), медиана 40 кг | одна модель должна работать и с метизами, и с арматурой — см. нормировку в [model.md](model.md) |
| **Крупные заказы юрлиц** | 1 % крупнейших заказов даёт 17,8 % проданного веса; строительные компании и перепродавцы — 54 % веса | часть объёма по истории не предсказуема |
| **Сезонность** | в июле сеть продаёт в 3,8 раза больше металла, чем в январе; дачный минимаркет работает с середины марта по ноябрь | календарные признаки, разделение «ноль» и «база закрыта» |
| **Жизненный цикл ассортимента** | позиции вводятся и выводятся, пункт выдачи открылся в 2023 году | ряд существует не всё время — см. [preprocessing.md](preprocessing.md) |
| **Дефицит** | товар заканчивается, продажи падают до нуля при наличии спроса | продажи — нижняя граница спроса, главное ограничение модели |
| **Зависимость от цен на металл** | индекс цен `metal_price_index` | пока не используется, кандидат в признаки |
| **Разные единицы** | 54 % веса продаж — метры, 31 % — листы, 12 % — штуки | метрики считаются в килограммах — см. [metrics.md](metrics.md) |

Кроме того, в данных есть недельный ритм продаж, совместные покупки товаров в одном заказе
и затоваривание — остатки, которые долго не продаются.

## Формат значений

- Даты — `YYYY-MM-DD`, время заказа `sales_orders.created_at` — `YYYY-MM-DD HH:MM:SS`,
  иногда с долями секунды (в pandas: `pd.to_datetime(..., format='ISO8601')`).
- Логические значения — `t` / `f` (так их выгружает PostgreSQL).
- Пустое значение — пустое поле, например `customer_id` у анонимной розничной покупки
  или `discontinued_on` у позиции, которая продаётся до конца периода.
- `products.attributes` — JSON с размерами, покрытием, цветом и т. п.
- Количество во всех документах — в единицах товара (`m`, `pcs`, `sheet`, `roll`, `pack`, `kg`),
  `products.kg_per_unit` переводит его в килограммы.
- Продажами считаются строки заказов со статусом `completed`.

## Использование

pandas читает файлы напрямую:

```python
import pandas as pd

orders = pd.read_csv('data/sales_orders.csv.gz')
orders['created_at'] = pd.to_datetime(orders['created_at'], format='ISO8601')
```

Модель прогноза обучается на датасете без PostgreSQL:

```bash
python -m sales_analytics.forecasting train --data data
```

Датасет выгружается из базы командой (папка — `DATASET_DIR` в `.env`, по умолчанию `data/`):

```bash
python -m sales_analytics.storage export
```

## Почему CSV, а не дамп базы

Выгрузка лежит в `data/` в виде `{таблица}.csv.gz` — по файлу на таблицу, около 25 МБ.

- **Читается без PostgreSQL.** `pandas.read_csv` открывает файл напрямую, модель обучается
  командой `train --data data`. Порог входа для проверяющего — Python и `pip install`.
- **Воспроизводимость.** Файлы сжаты gzip без даты в заголовке и отсортированы по первичному
  ключу, поэтому повторная выгрузка тех же данных даёт байт в байт те же файлы, а git видит
  только реальные изменения.
- **Один формат — два источника.** `load_demand_data()` читает базу, `load_demand_data_csv()` —
  датасет, оба возвращают один и тот же объект `DemandData`. Остальной код не знает, откуда
  пришли данные, и результаты на базе и на датасете совпадают.
- **Почему не Parquet.** Parquet компактнее и быстрее, но для таблиц такого размера выигрыш
  невелик, а CSV открывается любым инструментом, включая Excel и текстовый редактор.

## Какие таблицы использует прогноз

Из 17 таблиц модель прогноза сейчас читает шесть:

| Таблица | Для чего |
|---|---|
| `branches` | формат базы и дата открытия |
| `products` | категория, единица, вес единицы, даты ввода и вывода |
| `stock_movements` | дата первого движения позиции по базе — начало ряда |
| `sales_orders`, `sales_order_lines` | продажи по выполненным заказам |
| `calendar` | рабочие дни и границы периода |

Остальные таблицы — цены, индекс металла, клиенты, закупки, перемещения — оставлены
для следующих шагов: учёта дефицита по остаткам, цены как признака и разделения спроса
на розницу и юрлиц.
